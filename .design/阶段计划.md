# 阶段计划

本文件不允许ai随意修改，如有必要向用户询问

星号表示当前阶段

已完成
  框架与设计
    `.agent/` 与 `.design/` 工作区、sele 最小闭环
    SPEC、DECISIONS、INDEX、设计规范骨架
  需求与方案
    首版范围：最小内核集成 Demo（打开/创建、增删、列表、批量写、统计、关闭/重开）
    技术栈：Kotlin + Compose + Material 3，minSdk 29，ABI arm64-v8a/x86_64
    包名 `top.zxionf.shio`，数据库位于应用私有目录
  工程脚手架（P1）
    Gradle 8.14.3 / AGP 8.13.0 / Kotlin 2.2.20 固定，Compose 单页可构建、可安装
    两个 ABI 的 `libshio_ffi.so` 入库，16 KB LOAD 对齐校验通过
  内核集成（P2）
    CMake 以 IMPORTED 目标链接内核产物，产出 `libshio_jni.so`
    JNI 句柄表、每句柄互斥量、错误码到 `ShioException` 的映射
    `NativeShio` / `ShioDatabase` / `ShioException` 接入完成
    模拟器冒烟 open → insert → get → list → close → 重开 通过
  功能实现（P3）
    `DemoViewModel` + `StateFlow`：打开/创建、关闭、重开、刷新、增删、批量写、统计
    单页 Compose：口令、路径与 ABI、记录列表、错误码与消息展示
    所有 native 调用留在单线程 IO 调度器，主线程不触 native
    横竖屏切换后打开状态、列表、统计与口令输入保留
    模拟器验证：添加、删除、批量写、刷新、统计、关闭/重开、错误口令 INVALID_KEY

*设备验证（P4）
  x86_64 模拟器与 arm64 真机完整操作，杀进程后重开数据仍在
  错误口令返回 INVALID_KEY；关闭后写入返回 CLOSED；双实例返回 LOCKED
  stats 的 format_version、key_id、db_bytes 与操作结果一致
  记录设备型号、系统版本与结果
