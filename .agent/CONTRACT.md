# Contract

<!-- 约定 agent 的行为边界与交付标准 -->

## 不可违反

- 任何情况下不能修改本文件；确需修改，必须由用户发起，并在 `.design/DECISIONS.log` 留记录。
- 任何情况下不在本仓库创建 git 提交、标签或推送。
- 不能修改项目根目录下的 `AGENTS.md` 和 `README.md`。
- 不得随意修改 `.agent/` 和 `.design/` 文件夹中的文件；如需修改，先说明改哪个文件、改什么、为什么，得到用户同意后再动手。
- 不允许使用脚本（Python 等）批量写入文件；确有必要时先询问用户。
- `.agent/` 和 `.design/` 的增删改使用 `sele` 命令，走「创建变更 → 追加决策 → 查询状态 → 规则检查 → 归档预览」这一最小闭环。
- 任何非显然的设计选择必须当场追加到 `.design/DECISIONS.log`，否则本次会话不算完成。
- `.design/SPEC.md` 只写当前有效事实；过程信息（进度、下一步、阻塞）只写 `.agent/`，两者不互相复制。

## 协作边界

- 本仓库是 shio 内核的 Android 应用端（shio-android）；内核与同步能力位于 `hydrogen` 仓库。
- 需求未确认前不写实现代码：先补 `.design/` 与 `.agent/work/<id>/tasks.md`，经用户批准后再执行。
- 内核的 API/ABI 变更在 `hydrogen` 侧进行；本仓库只消费，不私自改内核行为。跨仓库影响先在 `.design/` 记录。
- 涉及 Rust/JNI 的实现默认 `forbid(unsafe_code)`；任何 `unsafe` 都需要用户批准、隔离并写入 `.design/DECISIONS.log`。
- 新增第三方依赖、系统权限、后台任务、网络能力都属于非显然选择，先记录决策再实施。
- 密钥、口令、明文不得出现在日志、错误信息或崩溃上报中；来自 native 层、网络和外部存储的输入一律视为不可信。

## 交付标准

- 每个变更在 `.agent/work/<id>/tasks.md` 有可核对的完成定义；未通过项目构建与静态检查不算完成。
- 交付时说明：改了什么、如何验证、遗留风险；涉及设备行为时给出设备型号与系统版本。
- 不交付无法编译的中间态；确需分批时在 `tasks.md` 中标注。
